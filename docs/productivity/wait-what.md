# wait-what

## What it does

`wait-what` is the corrective for a message that did not land. Invoking it
stops the current direction and asks for a re-pitch: a little context, in
ASD-STE100 Simplified Technical English, using the ubiquitous language from
`CONTEXT.md` (following `CONTEXT-MAP.md` to the right context when the repo
has more than one).

It exists because the usual fix, "explain that again", reproduces the same
failure: the same vocabulary, the same density, the same assumptions. The
re-pitch is constrained instead: shorter sentences, fewer idioms, one idea
per sentence, and the project's own glossary terms so the words mean what
the repo says they mean.

## When to reach for it

Type `/skill:wait-what` the moment a message leaves you confused rather
than informed. It is user-invoked and deliberately blunt; there is no
polite phrasing to remember.

## Common questions

**What is Simplified Technical English?**
ASD-STE100: a controlled language with a restricted vocabulary and short,
direct sentences. It exists for exactly this problem: instructions that must
not be misread.

**Why insist on `CONTEXT.md` terms?**
Shared vocabulary is the cheapest comprehension win available. If the repo's
glossary defines "cancellation", the re-pitch should use that word, not a
synonym that quietly means something else.

**Is this an insult to the writer?**
It is a repair request, not a judgment. The message did not land; the
cheapest fix is a constrained re-pitch, and everyone keeps moving.

## It's working if

- The re-pitch is shorter and plainer than the original message, not a
  rewording of it.
- It uses the glossary terms, so the next exchange agrees on what the words
  mean.
- The confusion is resolved in the immediate follow-up instead of compounding
  into a wrong plan.
