# triage

## What it does

`triage` moves bug reports and feature requests through a small state
machine of **triage roles**, and writes agent-ready briefs for the ones that
graduate. It runs on the `docs/bugs/` and `docs/tasks/` file substrate, no
issue tracker required. Everything it writes to a doc during triage carries
the disclaimer "*This was generated by AI during triage.*"

The roles: two categories (`bug`, `enhancement`) and five states
(`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`,
`wontfix`), recorded in the doc's frontmatter. A new bug doc (`status:
reported`) enters `needs-triage` and moves outward from there; conflicting
states are flagged and asked about, never silently resolved.

Invoked with a natural-language request ("show me what needs my attention",
"move the search-request to ready-for-agent"), it shows three attention
buckets oldest-first, then works one item: gather context, check
**redundancy** (an existing implementation by domain concept makes it a
wontfix pointing at the code) and **prior rejection** (the
`docs/tasks/out-of-scope/` knowledge base of consciously ruled-out
requests), **verify the claim** (reproduce the bug or confirm the behavior
is absent), and **grill it into shape** with `/skill:grilling` and
`/skill:domain-modeling` when it needs fleshing out. Outcomes: an agent
brief for `ready-for-agent`, a brief explaining why it cannot be delegated
for `ready-for-human`, specific questions for `needs-info`, and a close-out
for `wontfix` (already-implemented points at the code; rejected enhancements
land in the out-of-scope KB).

A **spot-fix path** handles trivial bugs directly: regression test red on
the unfixed code, fix, full suite, doc closed and archived. If the trivial
fix surprises you, it stops and promotes to a real bug ticket instead.

## When to reach for it

Type `/skill:triage` when bugs and requests are piling up and need sorting
into agent-ready work. It is user-invoked: the maintainer drives it in
natural language. Tickets that `to-tickets` produced are already agent-ready
and skip triage.

## Common questions

**Why a state machine instead of labels?**
The roles are canonical and the state lives in the file's frontmatter, so
"what needs attention" is a grep over `docs/bugs/`, not a query against an
external system.

**What goes in an agent brief?**
Everything a fresh agent needs to implement without re-asking: the verified
reproduction, the decided behavior, constraints, and acceptance evidence.
The brief is durable; the conversation was not.

**When is a rejected request written to the out-of-scope KB?**
Only genuine rejections of enhancements. Already-implemented requests point
at the existing code instead; the KB records "no, deliberately", not
"already exists".

**Can triage just fix it?**
Only the spot-fix path, only for trivial bugs, always red-test-first, and it
stops the moment the fix is deeper than it looked.

## It's working if

- The queue view shows untriaged, in-progress, and re-answered items oldest
  first, with counts, and never re-asks questions the reporter already
  answered.
- Claims were verified before briefs were written: a confirmed reproduction
  (or confirmed absence) backs every `ready-for-agent` brief.
- Grilling sharpened the request with `CONTEXT.md` and ADRs updated inline
  as decisions landed.
- `wontfix` closures match their reason: implemented ones cite the code,
  rejected ones cite (or join) the out-of-scope KB.
- Every AI-written note carries the triage disclaimer.
