Tool results and error messages name artifact paths in POSIX form on every platform. A Windows host previously interpolated `relative()` directly, so a creation result, a refusal, or the resolution path `tw_resolve_uncertainty` returns read `docs\tasks\...`, which a caller then pastes back into path arguments and compares against prose that uses `docs/tasks/...`. A single normalization seam now produces the same string on Linux, macOS, and Windows; paths on another drive still read as absolute, so the write lockdown keeps refusing them.
